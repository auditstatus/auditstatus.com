# Reports

Each verification writes `report.md` for people, `report.json` for machines, and `badge.json` for a badge. This page explains the statuses, the parts of the report, and each finding: what it means and what to do about it. Findings are grouped by their check name, which the report shows in parentheses after the severity.


## Statuses

| Status  | Shown as              | Meaning                                                                                                                                       |
| ------- | --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `pass`  | passing               | Every check ran and matched its reference.                                                                                                    |
| `warn`  | passing with warnings | Passed, with findings worth attention. Counts as passed.                                                                                      |
| `fail`  | failing               | The server differs from its references, or its evidence is invalid.                                                                           |
| `error` | inconclusive          | A check could not be completed (a reference was unreachable, the server did not answer, a check lacked permissions). Never counts as passing. |

Each finding has a severity: `fail`, `warn`, `error` (the check could not complete) or `info` (context). A server's status is the worst of its findings, in the order `fail`, `error`, `warn`, `pass`. The overall status is the worst server's. Settings in `policy` choose between `fail` and `warn` for some findings; the tables below name them.


## report.md

The report starts with the overall status, how many servers passed, and the verifier's version, then a table with one row per server:

| Column         | Meaning                                                                                                                                               |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| Server         | The server's name in the verifier configuration.                                                                                                      |
| Status         | The server's status.                                                                                                                                  |
| Evidence       | The evidence level: software evidence, TPM, TPM + IMA, AMD SEV-SNP, Intel TDX, or a combination. See [How it works](how-it-works.md#evidence-levels). |
| Services       | How many services were checked.                                                                                                                       |
| Processes      | How many application processes were inspected across the services.                                                                                    |
| Code explained | Executables and libraries that matched a reference, out of all those the processes run or map.                                                        |

Then a section per server: when the evidence was collected, by which attester version, on which operating system, and at which level; one line per service; and the findings, failures first. For a directory service the line shows the commit (linked to the repository), `files verified/tracked`, `build verified/files`, `<ecosystem> packages verified/total`, and the processes with their runtimes. For a container, the image and digest, the number of changes from the image, and the processes. Findings list up to 50 items each, then "… and N more"; `report.json` has the same items and, for most findings, the total.

Values from the evidence are escaped, so a server cannot put links or markup into the report.


## report.json

| Field              | Content                                                                                                                                                                                                                                                                                 |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `type`, `version`  | `auditstatus-report`, `2`                                                                                                                                                                                                                                                               |
| `generatedAt`      | When the report was written.                                                                                                                                                                                                                                                            |
| `verifier.version` | The verifier's version.                                                                                                                                                                                                                                                                 |
| `services`         | Each configured service's name, repository, and artifact or image signer.                                                                                                                                                                                                               |
| `status`           | The overall status.                                                                                                                                                                                                                                                                     |
| `servers[]`        | `name`, `host`, `status`, `level`, `hardware`, `collectedAt`, `attesterVersion`, `os`, `findings` (`severity`, `check`, `message`, optional `service` and `detail`), `summary` (processes; code by reference source; global packages; monitor), and `services` (per-service summaries). |
| `files`            | Paths of the three files written.                                                                                                                                                                                                                                                       |


## Findings

### evidence, transport

| Message                                                                                  | Severity | What to do                                                                                                                                                            |
| ---------------------------------------------------------------------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Could not collect evidence                                                               | error    | The verifier could not reach the attester. The detail has the SSH or kubectl error: check the host, the key, `known_hosts`, and `auditstatus doctor --role verifier`. |
| Unsupported evidence format ... (the attester and verifier versions may differ)          | fail     | Upgrade the attester or the verifier so both use evidence version 2.                                                                                                  |
| Evidence does not match the evidence schema                                              | fail     | The evidence is malformed. Run `auditstatus collect` on the server and compare versions.                                                                              |
| Evidence does not answer this verifier's nonce (stale or replayed)                       | fail     | Something other than the attester answered. Investigate.                                                                                                              |
| Evidence timestamp is outside the accepted window                                        | fail     | The server's clock is off, or collection took longer than `policy.maxEvidenceAgeSeconds`. Fix the clock (NTP).                                                        |
| Evidence cannot be canonicalized, Evidence digest does not match its contents            | fail     | The evidence was edited after it was collected. Investigate.                                                                                                          |
| Evidence names a service more than once                                                  | fail     | An attester never reports a service twice. Investigate.                                                                                                               |
| Processes run executables or map files that the evidence does not list with their hashes | fail     | An attester lists every executable and mapped file of the processes it inspects. Investigate.                                                                         |

| `<label>: Bundler X (on RUBYLIB) could not be compared with the published gem`                                                                                                                          | fail or error                        | RubyGems.org has no such version (fail), or could not be reached (error).                                                                                                                                                                                                                  |
| `<label>: deleted-backing`, `replaced-backing`                                                                                                                                                          | warn                                 | A mapped library was upgraded without a restart. Restart the process.                                                                                                                                                                                                                      |
| `<label>: ld.so.preload could not be read: what the dynamic linker preloads is not known`                                                                                                               | error                                | The attester could not read `/etc/ld.so.preload` (the linker finding `ld.so.preload-unreadable`), so a library preloaded into every program would go unseen. Give the attester read access, or check what replaced the file.                                                               |
| `<label>: some checks could not run (missing permissions?)`                                                                                                                                             | error                                | Give the attester `CAP_SYS_PTRACE` and `CAP_DAC_READ_SEARCH`, or run it as root. Check with `auditstatus doctor`.                                                                                                                                                                          |
| `<label>: executable was replaced after the process started (restart required)`                                                                                                                         | warn                                 | Restart the process.                                                                                                                                                                                                                                                                       |
| `<label>: tracked files, build output or installed packages changed after the process started`                                                                                                          | `policy.modifiedAfterStart`          | The process may run code that is no longer on disk, or a file that was modified and restored. Restart it after each deploy; investigate if no deploy explains it.                                                                                                                          |
| `<label>: more files changed after the process started than the server reports`                                                                                                                         | `policy.modifiedAfterStart`          | The same, over `limits.maxChangedFiles`.                                                                                                                                                                                                                                                   |
| `<label>: the status of tracked files, build output, installed packages or their directories changed after the process started`                                                                         | `policy.metadataChangedAfterStart`   | A new mode or owner, contents restored with an earlier modification time, or a directory whose entries changed: a file added and removed again (it may have been loaded in place of another), or a configuration file replaced. Restart the process; investigate if no deploy explains it. |

### code

| Message                                                                      | Severity                                   | What to do                                                                                                                                                                                                                                                                                                                                    |
| ---------------------------------------------------------------------------- | ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| N of M executables and libraries match a reference                           | info                                       | Followed by the count per source: `git`, `build`, `artifact`, each package ecosystem, `packages` (global packages), `image`, `node`, `pinned`, `checksums` and `distro`.                                                                                                                                                                      |

### retry

| Message                                                                                        | Severity | What to do                                                                                                                                                             |
| ---------------------------------------------------------------------------------------------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Collected again after N seconds; the first attempt was X                                       | warn     | X is failing or inconclusive. With `policy.retryAfterSeconds`. The detail lists what the first attempt found. If a deploy explains it, nothing; otherwise investigate. |
| Collected again after N seconds; the first attempt was failing and the second was inconclusive | fail     | The server failed, then could not be checked again. A failure is not traded for an inconclusive result. Investigate.                                                   |
