# Languages

Audit Status works with any language. For every service it compares the deployed files with the public commit (or an attested release manifest), inspects every process running from the service, and explains every running executable and mapped library by a reference. What differs between languages is how installed dependencies and compiled code are checked. Each guide below says which lockfile is read, which reference each package is compared with, and how to set up the project, the attester and the verifier.

| Language                        | Lockfile                                                                                                       | Reference                                                                                                           | What is verified                                                                                                   | Guide                      |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | -------------------------- |

| Python                          | `uv.lock`, `pylock.toml`, `poetry.lock`, `Pipfile.lock`, `requirements.lock` or `requirements.txt` with hashes | PyPI wheel by pinned SHA-256, compared through its `RECORD`                                                         | `site-packages` of each virtual environment, `bin/` scripts, the environment's start-up hook                       | [python.md](python.md)     |

## Common to every language

* The lockfile is read at the deployed commit, from the verifier's own clone of the public repository, never from the server.
* Files the deploy generates and git ignores are listed but not compared, unless `build` in the verifier configuration covers them. See [configuration](../configuration.md).
* Package checks are named `packages:<ecosystem>` in the report. A package that cannot be checked is reported by `policy.unverifiablePackages` (default `fail`). A reference that cannot be fetched makes the result inconclusive, never passing.
* A process is inspected when its working directory is inside the service root (or the service's `cwd`) and, when `user` is set, it runs as that user.
* Restart processes after each deploy: a tracked file or build output changed after a process started fails (`policy.modifiedAfterStart`).
* `auditstatus init` detects the lockfiles in a repository and writes starting configuration for both sides.

See [how it works](../how-it-works.md), [the attester](../attester.md), [the verifier](../verifier.md) and [containers](../containers.md).
